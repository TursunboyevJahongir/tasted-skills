# 5. Мультиагентная Работа (`Orca`) и Независимое Ревью Архитектуры и Кода

[🇺🇿 O'zbekcha](../05-multi-agent-and-context-handoff.md) | [🇬🇧 English](../en/05-multi-agent-and-context-handoff.md) | **🇷🇺 Русский**

⬅️ [Вернуться к оглавлению практик](README.md)

- **Связка инструментов:** [**Orca**](../../reviews/ru/developer-tools/orca.md) (`orca orchestration`) + [**elephant-goldfish-model**](../../reviews/ru/architecture/elephant-goldfish-model.md) + [**graphify**](../../reviews/ru/architecture/graphify.md)
- **Задачи:** Крупные фичи, параллельная разработка в нескольких ветках/worktree, цепочки нескольких ИИ из одного промпта и глубокое ревью кода и архитектуры.

---

## 1. Зачем использовать их в связке? (Общая выгода)

1. Когда одна и та же модель пишет код и сама же его проверяет, она склонна оправдывать собственные ошибочные допущения.
2. Ручное копирование контекста между терминалами (`Codex` -> `Claude Code` или `Gemini`) тратит время и токены.

**Что даёт эта связка:**
- `Orca` из одного промпта (`orca orchestration worker-start`) запускает вспомогательных субагентов прямо в Chat UI с живыми карточками и собирает итог в один тред;
- В любой момент можно вызвать вторую AI-модель либо **с контекстом задачи** (`Orca` воркеры — для проверки соответствия требованиям), либо **с чистым листом без памяти (*Goldfish*)** (`elephant-goldfish-model` — для жёсткой критики архитектуры).

---

## 2. Когда нужен «Контекстный Кросс-Review», а когда «Review без памяти (Goldfish)»

Два режима проверки решают разные задачи:

| Ситуация | Какая связка используется | Почему именно так |
|---|---|---|
| **Проверка написанного кода/diff'а и соответствия требованиям** | [**Orca**](../../reviews/ru/developer-tools/orca.md) (`orca orchestration worker-start` — `Codex`, `Claude Code`, `Gemini`) | Ревьюер знает, *что именно* просил пользователь и *почему* выбрано такое решение, но смотрит на код глазами другой модели (*«Codex написал -> Claude/Gemini проверил»*). |
| **Проверка архитектурного плана, дизайн-дока или расхождения Документация-Код** | [**elephant-goldfish-model**](../../reviews/ru/architecture/elephant-goldfish-model.md) (`egm-review`, `egm-drift-report`) | Здесь история переписки **вредит** — субагенты без памяти (*Goldfish*) читают документ и код с нуля, сразу вскрывая неявные допущения и лишнюю сложность (YAGNI). |

---

## 3. Дополнительные возможности

### 1) Решение «неразрешимых» архитектурных противоречий по ТРИЗ (`egm-brainstorm` / `inventive-catalyst`)
Когда система упирается в дилемму (*«ускоряем — теряем надёжность, повышаем надёжность — падает скорость»*):
- Субагент **ТРИЗ (`inventive_catalyst`)** внутри `egm-brainstorm` помогает найти инженерное решение, устраняющее само противоречие без компромисса.

### 2) Карта и авто-документирование незнакомого репозитория за 10 минут (`graphify` + `egm-bootstrap`)
При входе в большой проект без документации:
1. Строим локальный AST-граф (`0` токенов) через [**graphify**](../../reviews/ru/architecture/graphify.md);
2. Запускаем `egm-bootstrap`, который распределяет поддеревья папок между воркерами и создаёт точные модульные `README.md` по реальному коду.

### 3) Параллельная работа в нескольких Git Worktree без конфликта симуляторов (`Orca` + `agent-device`)
- `Orca` разводит задачи по отдельным git worktree, а [**agent-device**](../../reviews/ru/mobile/agent-device.md) и [**simslim**](../../reviews/ru/mobile/simslim.md) изолируют сессии симуляторов между ветками.
