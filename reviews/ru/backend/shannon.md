## 1. Что это и как работает?

> [!IMPORTANT]
> **Простыми словами (Главная задача и польза):** Перед крупным релизом атакует локальный или staging-сервер реальными эксплойтами (`Auth bypass`, `IDOR`, `SQLi`, `XSS`), проверяя защиту на деле (`0` расхода токенов в простое через `hacker-test`; строго не для прода).

`Shannon` (`AGPL-3.0`) — это не статический линтер и не пассивный промпт ревью кода, а автономный **White-Box AI-пентестер**, который реально атакует запущенное веб-приложение и HTTP API для подтверждения уязвимостей:

1. Команда `npx @keygraph/shannon@latest start -u <url> -r <repo>` поднимает **Docker + Temporal (`temporalio/temporal:1.7.0`) + Playwright CLI + агентный рантайм Pi**.
2. Монтирует исходный код репозитория в `read-only` режиме, строит карту маршрутов, auth-гардов и потоков данных (`pre-recon` и `recon`).
3. Запускает агентов реальной эксплуатации по **5 классам OWASP**:
   - **Broken Authentication** (`exploit-auth`)
   - **Broken Authorization / IDOR** (`exploit-authz` — доступ к чужим данным между пользователями/организациями)
   - **Injection** (`exploit-injection` — SQL/NoSQL/Command injection)
   - **XSS** (`exploit-xss`)
   - **SSRF** (`exploit-ssrf`)
4. **Принцип «No exploit, no report»:** В итоговые PDF, Markdown, JSON и SARIF 2.1.0 отчёты попадают только реально проэксплуатированные уязвимости (`status: exploited`) с готовым PoC.

## 2. Сильные и слабые стороны

### Сильные стороны
- **Закрывает пустующую нишу безопасности:** `elephant-goldfish-model` находит архитектурные расхождения, `sentry` ловит ошибки в рантайме, а `Shannon` проверяет реальные HTTP-запросы на IDOR, обход прав доступа и инъекции.
- **Работает с существующей подпиской `Codex` (`ChatGPT Plus/Pro`):** Отдельный дорогой API-счёт не обязателен — подключается через `pi` (`SHANNON_USE_PI_AUTH=1` + `SHANNON_AI_MODEL=openai-codex:gpt-5.5` или `gpt-6-sol`) *(примечание: в v2 убрана поддержка OAuth-подписки Claude Code, она осталась только в `@1.9.0`)*.

### Слабые стороны и накладные расходы
- **Тяжёлый и долгий запуск:** Требует Docker + Temporal, полный прогон занимает **1 – 1.5 часа** и расходует заметную квоту модели.
- **Блокировки Cyber Safeguards у OpenAI / Anthropic:** Защитные фильтры провайдеров могут прервать скан посередине — перед запуском обязательна проверка `--validate-model` (и при необходимости верификация `chatgpt.com/cyber`).
- **Только Web и HTTP API:** Не проверяет нативные бинарники iOS/Android, сырые бинарные TCP-протоколы и CVE зависимостей.

## 3. Безопасность и очистка перед установкой (Санитаризация)

- **Уровень риска:** `Средний` *(разрушает данные БД при ошибочном запуске на production)*
- **Проверенные точки:** `plugins/shannon/skills/shannon/SKILL.md`, `compose.yml`, `docs/safety.md`, лицензия `AGPL-3.0`.
- **Строгие правила эксплуатации:**
  1. **Никогда не направлять на production:** Агенты создают пользователей, отправляют формы и изменяют/удаляют записи. Разрешён запуск только против локального сервера (`http://host.docker.internal:<port>`) или изолированной тестовой БД.
  2. **Не устанавливать родной `plugins/shannon` глобально:** Чтобы не грузить крупный `llms-full.txt`, вместо него создан минимальный (~40 токенов) скилл `hacker-test`, срабатывающий строго по фразе `"hacker test"`.
  3. **Сканировать только собственные доверенные репозитории:** Из-за риска prompt injection через чужой исходный код.

## 4. Наш подход: почему мы создали свой [`hacker-test`](../../../skills/hacker-test/SKILL.md) вместо установки родного плагина

Пентест нужен не каждый день, а перед крупными релизами. Из-за этого возникают две крайности: **1)** если поставить официальный `plugins/shannon` глобально, с ним висит тяжёлый `llms-full.txt`; **2)** если вообще ничего не подключить, через месяц забываются и название инструмента, и флаги `host.docker.internal`, `pi`-авторизации и `--validate-model`.

**Как мы решили обе проблемы:**
1. Сам `Shannon` и его плагин постоянно не устанавливали (`0` фоновых процессов и лишнего веса).
2. Внутри этого репозитория создали компактный (~45 токенов) скилл-обёртку [**`skills/hacker-test/SKILL.md`**](../../../skills/hacker-test/SKILL.md) и синхронизировали его во все агенты (`Antigravity`, `Claude Code`, `Codex`):
   ```bash
   skillshare install TursunboyevJahongir/tasted-skills -s hacker-test -g && skillshare sync -g
   ```
3. В обычной разработке он никак не мешает, но стоит в любом проекте написать **`"hacker test"`**, агент сразу:
   - проверяет защиту **не-production** (`http://host.docker.internal:<port>` или тестовая БД + явное подтверждение);
   - прогоняет 10-секундную проверку `--validate-model`;
   - запускает `npx @keygraph/shannon@latest start` и переводит подтверждённые PoC-уязвимости в точечные исправления кода.

## 5. В каких задачах полезно?

- **Когда использовать:** Перед крупным релизом на локальном Docker/staging стенде для проверки Web и Backend API на IDOR, обход авторизации, SQLi, XSS и SSRF (по команде `"hacker test"`).
- **Когда не использовать:** На production-серверах, для мелких UI-правок, а также для нативных мобильных приложений и бинарных TCP-сервисов.
