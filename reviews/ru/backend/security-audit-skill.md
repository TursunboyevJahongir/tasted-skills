## 1. Что это и как работает?

> [!IMPORTANT]
> **Простыми словами (Главная задача и польза):** Проверяет исходный код Backend, Web и **мобильных приложений (`deep-link`, `WebView`)** глазами атакующего без запуска Docker, отсеивая ложные тревоги через второго независимого субагента-проверяющего.

Выделенный из внутренней системы поиска уязвимостей Cloudflare (`vulnerability harness`) **100% локальный, агент-нейтральный White-Box скилл аудита безопасности кода** (`MIT`, `0` внешних npm-пакетов, `0` сетевых вызовов, `0` телеметрии, `0` хуков).

**6-фазный *Adversarial* механизм проверки:**
1. **Reconnaissance (`RECONNAISSANCE.md`):** Строит карту архитектуры, границ доверия (`trust boundaries`) и точек входа в `architecture.md` и `coverage-ledger.json`.
2. **Coverage-led Hunting (`HUNTING.md` + 12 модулей):** Запускает изолированных *Hunter*-субагентов по доменам: Web/Auth (`WEB-PROTOCOL-AND-AUTH.md`), изоляция тенантов и данных (`DATA-ISOLATION-AND-LIFECYCLE.md`), **мобильные `deep-link` / `WebView` / `IPC`** (`DESKTOP-MOBILE-AND-LOCAL-IPC.md`), AI prompt-injection (`AI-AND-LLM.md`), Cloud/IAM/Docker (`CLOUD-AND-DEPLOYMENT.md`) и CI/CD supply-chain (`SUPPLY-CHAIN-AND-RELEASE.md`).
3. **Adversarial Candidate Validation:** Каждый найденный кандидат передаётся **не тому агенту, который его нашёл**, а чистому независимому *Verifier*-субагенту, чья задача — **опровергнуть** находку по коду (отсекает ложный шум чеклистов).
4. **Structured JSON Output:** Статусы (`confirmed`, `needs_validation`, `rejected`) пишутся в `findings.json` и проверяются локальными `validate-findings.cjs` и `validate-coverage-ledger.cjs`.
5. **Independent Record Verification:** Финальные ссылки на код проходят повторную независимую сверку.
6. **Target-Neutral Report:** Сохраняет `REPORT.md`, `FINDINGS-DETAIL.md` и `NEEDS-VALIDATION.md` вне репозитория (`~/security-audit-skill/<repo>/run-<N>`), не засоряя git-дерево проекта.

## 2. Сильные и слабые стороны

### Сильные стороны
- **Широкий охват без Docker и поднятия серверов:** Проверяет не только HTTP API, но и **Expo / React Native / iOS / Android** (`deep-link`, `WebView`, локальное хранение), CLI-утилиты, GitHub Actions CI/CD, конфиги Docker/Cloud и LLM-интеграции.
- **Минимум ложных срабатываний:** Статус `confirmed` получают только доказанные нарушения границ доверия с реальным ущербом; внешние инфраструктурные вопросы выносятся в `needs_validation` без надуманной критичности.
- **Накопительные повторные прогоны:** Читает прошлый `coverage-ledger.json` и допроверяет только изменившийся код или незакрытые участки.

### Слабые стороны и накладные расходы
- **Расход квоты субагентов на полных профилях:** Режимы `standard` и `deep` на крупном репозитории могут вызвать `10–30+` субагентов — поэтому локально по умолчанию выставлен экономный профиль **`quick` / `scoped`**.
- **Не атакует живой сервер по HTTP:** Анализирует исходный код; для реального динамического взлома локального/staging стенда через браузер используется [`Shannon` (`hacker-test`)](shannon.md).

## 3. Безопасность и очистка перед установкой (Санитаризация)

- **Уровень риска:** `Низкий` *(`0` зависимостей, `65/65` локальных Node-тестов пройдено, `CRITICAL = 0`)*
- **Проверенные точки:** `SKILL.md`, все 14 `.md`-файлов, `validate-findings.cjs`, `validate-coverage-ledger.cjs` и `skillshare audit` (предупреждения `HIGH` вызваны лишь проверочным текстом `"Are there any eval(), exec()..."` внутри `ATTACK-CLASSES.md`).
- **Выполненная локальная санитаризация (`explicit-trigger-and-quick-default-1`):**
  1. **Сужен `description` во frontmatter `SKILL.md`:** Чтобы скилл (`22 KB`) не подгружался на обычных задачах по JWT/авторизации, авто-триггер ограничен явными запросами на аудит кода (`"security audit"`, `"xavfsizlik auditi"`, `"kod xavfsizligini tekshir"`, `"zaifliklarni top"`), а живой пентест оставлен за [`hacker-test`](shannon.md).
  2. **Профиль по умолчанию изменён со `standard` на `quick` / `scoped` (строка 120 `SKILL.md`):** Бережёт квоту субагентов, пока пользователь явно не запросит полный прогон `standard` или `deep`.

## 4. Совместимость и связка с [`Shannon` (`hacker-test`)](shannon.md)

Оба инструмента дополняют друг друга как **двухступенчатая проверка безопасности**:

| Критерий | **`security-audit`** *(Cloudflare — `✅ Использую`)* | [**`Shannon` (`hacker-test`)**](shannon.md) *(`👍 Хороший вариант`)* |
|---|---|---|
| **Механизм** | 6-фазный аудит исходного кода (`Hunter` + независимый `Verifier`) | Живая динамическая эксплуатация через Docker + Temporal + Playwright |
| **Охват** | Backend, Web, **Mobile (`iOS`/`Android`/`Expo`)**, CLI, Cloud/CI, LLM | Только запущенные Web-приложения и HTTP API |
| **Время и запуск** | Без Docker и серверов (`quick`/`scoped`: **3–10 мин**) | Нужен Docker + поднятый локальный/staging стенд (**1 – 1.5 часа**) |

## 5. В каких задачах полезно?

- **Когда использовать:** Перед релизом или мёрджем модулей авторизации, платежей, ролей/тенантов, мобильных deep-link/WebView, CI/CD-пайплайнов или всего репозитория без поднятия Docker (*«сделай security audit модуля auth»*).
- **Когда не использовать:** На мелких однострочных правках (`ponytail`) или когда нужно проверить живой staging-сервер реальными браузерными эксплойтами (тогда `"hacker test"`).
