## 1. Что это и как работает?

Быстрый нативный CLI-инструмент, который читает и управляет десктопными приложениями напрямую через системное дерево **Accessibility (`AX`)**. Каждая команда возвращает структурированный JSON (`ok`, `data`, `error`).

Основная цепочка работы (`observe → act → verify`):
1. `agent-desktop snapshot --app "Google Chrome" --skeleton -i --compact` — получает компактную карту интерактивных элементов окна;
2. `agent-desktop snapshot --root @<id>:e<N> --compact` — точечно раскрывает нужную ветку без переполнения контекста;
3. `agent-desktop click @<id>:e<N>` или `set-value @<id>:e<N> "<текст>"` — отправляет семантическое действие напрямую элементу.

**Главное преимущество (`Headless`-режим по умолчанию):** В стандартном режиме инструмент не двигает курсор мыши пользователя, не перехватывает клавиатуру и не выводит окно на передний план (работает полностью в фоне без кражи фокуса).

## 2. Сильные и слабые стороны

### Сильные стороны
- **Работает с уже авторизованным Chrome:** В отличие от Playwright, не требует каждый раз поднимать чистый профиль — проверяет открытое окно `Google Chrome` в фоне.
- **Управляет iOS Simulator (`Device Hub`):** Через окно Xcode `Device Hub` видит и нажимает внутренние элементы React Native / UIKit по дереву `AX`.
- **Безопасный контроль повторов:** Возвращает `disposition.delivery` и `retry: safe`, предотвращая случайное двойное нажатие кнопок.

### Слабые стороны и ограничения
- Не видит внутренние элементы окон, отрисованных целиком на GPU/OpenGL/Metal (например, экран Android-эмулятора или `<canvas>`/WebGL) — для Android используется `adb`, а для троттлинга сети/CPU — Chrome DevTools.
- На macOS требуется системное разрешение Accessibility (и Screen Recording для скриншотов).

## 3. Безопасность и правила использования

- **Уровень риска:** `Средний` *(управляет реальными открытыми приложениями и авторизованными сессиями)*
- **Обязательные правила:**
  1. **Не включать `--headed` без явного разрешения пользователя:** Режим `--headed` перехватывает физический курсор и клавиатуру; при ошибке в `headless` нельзя скрытно переключаться на `--headed`.
  2. **Работать только с целевым приложением (`--app`):** Не трогать посторонние мессенджеры, почту или системные настройки.
  3. **Использовать `--skeleton`, `--compact` и `--root`:** Читать дерево по частям, чтобы не раздувать контекст на больших страницах.

---

## 4. Совместимость с нашими текущими инструментами

- **Web (`Google Chrome`) и десктопные приложения macOS:** `agent-desktop` остаётся **на 100% основным** фоновым инструментом проверки.
- **Mobile и TV (`iOS`, `Android`, `tvOS`, `Android TV`):** Управляются через [`agent-device`](../mobile/agent-device.md) (`agent-desktop` + `Device Hub` остаётся резервом для iOS).
- Для прямого вызова из C/Python/Node/Swift без запуска CLI рядом установлен скилл `agent-desktop-ffi`.

---

## 5. В каких задачах полезно?

- **Когда использовать:** Проверка локальных веб-приложений в `Google Chrome` и фоновая автоматизация десктопных GUI-программ на macOS.
- **Когда не использовать:** В мобильных и TV-симуляторах/эмуляторах (используется [`agent-device`](../mobile/agent-device.md)) или при глубоком профилировании сети и CPU-троттлинга (нужен Chrome DevTools).
